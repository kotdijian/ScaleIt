# Scale Bridge 0.1.0

COLMAPのカメラ情報と対応写真から、写し込んだスケールの目盛りを手動で指定し、実寸の縮尺を求めるローカルアプリです。縮尺補正済みCOLMAPと、Metashape Standardへ戻すためのAgisoftカメラXMLを出力します。OBJ/PLYは不要です。

**計算とCOLMAPの往復は合成データで検証済みです。Metashape StandardへのXML読み込み・メッシュ生成後の実寸保持は、まだ実機検証していません。出力XMLは実験段階です。**

## Macでの起動

Python 3.12を推奨します。フォルダを展開し、ターミナルでこのREADMEがあるフォルダに移動してください。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python gui.py
```

初回に必要なパッケージをダウンロードします。以降の計算と画像表示はローカルで行い、写真はアップロードしません。PySide6/pycolmapのMac用wheelが使用するPython/OSに対応している必要があります。Linux・Python 3.12・pycolmap 4.2.1で検証しました。M3 Mac上では未検証です。

## Windows 11での起動

Python 3.12の64bit版とPython Launcherをインストールしてください。リポジトリを取得・展開し、PowerShellで `ScaleBridge` フォルダ（このREADMEと `gui.py` がある場所）を開きます。

初回セットアップと起動：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe gui.py
```

2回目以降は同じフォルダで次だけを実行します。

```powershell
.\.venv\Scripts\python.exe gui.py
```

仮想環境を有効化するスクリプトは使用しないため、PowerShellの実行ポリシーを変更する必要はありません。`py` が見つからない場合はPython Launcherのインストールを確認してください。パッケージのインストールが失敗した場合はPython 3.12・64bit版であることを確認してください。

Scale Bridgeの計算・画像表示にはCUDA、PyTorch、SAM3は不要です。初回の依存パッケージ取得にはネット接続が必要ですが、その後の画像表示と縮尺計算はローカルで行います。Windows 11実機での起動・Metashapeとの往復は未検証です。

## 工程ごとに使用する画像

このREADMEの推奨設定（COLMAP書き出し時にピンホール変換ON）では、画像を次のように使います。

| 工程 | 操作するアプリ | 使用する画像 | 対応するカメラ情報 |
| --- | --- | --- | --- |
| スケールの目盛りを打点し、縮尺を計算 | Scale Bridge | **COLMAPと一緒に書き出した歪み補正画像** | 書き出したCOLMAPデータ |
| 縮尺補正後のカメラ配置でメッシュを生成 | Metashape | **最初のアラインメントに使用したオリジナル入力画像** | Scale Bridgeが出力した `scaled_cameras.xml` |

**Metashapeへ戻してメッシュを生成する場合も、Scale Bridgeでの打点は歪み補正画像に対して行います。打点後にオリジナル画像で打ち直す工程はありません。** オリジナル入力画像を使うのは、後段のMetashapeでのメッシュ生成です。

Scale Bridgeは、歪み補正画像とCOLMAPのカメラ情報から縮尺を計算します。その縮尺を元のAgisoft XMLのカメラ配置へ反映し、オリジナル入力画像用のキャリブレーションを保持した `scaled_cameras.xml` を出力します。このため、打点とメッシュ生成で使用する画像が異なります。メッシュ生成へ戻す入力は、この補正済みXMLです。

## Metashapeからのデータの書き出し

### 1. 同じアラインメントを準備

スケールが写っている写真を含めてAlign Photosを実行し、プロジェクトを保存します。COLMAPとXMLは、同じチャンク・同じアラインメントから続けて書き出します。その間に再アラインメントやカメラの最適化を行わないでください。両形式に同じ全アライン済みカメラを含めます。

### 2. COLMAP形式と対応画像を書き出す

File → Export → Export Cameras（ファイル → エクスポート → カメラをエクスポート）でColmap形式を選び、新しい出力先を指定します。以下は通常の単眼写真・ローカル座標のワークフロー用の推奨設定です。項目の表示名や有効状態はMetashapeのバージョンによって異なります。

| 画面の項目 | 推奨設定 | 理由 |
| --- | --- | --- |
| 座標系 | Local Coordinates (m) | 地理・投影座標を使わないローカル処理 |
| イメージ | ON | カメラ情報と対応する歪み補正画像を同時に出力 |
| マスク | OFF | Scale Bridgeでは使用しない |
| タイポイント | OFFで可 | 新しい打点をカメラ情報から三角測量するため、既存点群は不要 |
| 基準点 | OFF | このワークフローでは使用しない |
| ピンホールカメラモデルへの変換 | ON | 歪み補正画像とピンホールのカメラ情報を使用 |
| 初期キャリブレーションに変換 | OFF | 初期キャリブレーションへの追加変換を行わない |
| バイナリエンコーディング | OFF | 内容を確認しやすいテキスト形式 |
| 選択したカメラのみをエクスポート | OFF | 全アライン済みカメラを含める |

**定型イメージ名は、XMLのカメララベルと一致する名前になるように設定してください。** 現在のScale Bridgeは、COLMAPの画像名のファイル名部分とXMLのカメララベルのファイル名部分を、拡張子・大文字小文字も含めて完全一致で照合します。`{filename}_{filenum}.jpg` のようなテンプレートは、連番の追加によってXMLと名前が異なる可能性があります。既定値だからそのまま使えるとは限りません。写真名には空白・タブを含めず、各写真のファイル名を一意にしてください。

出力後、`images.txt` の画像名とXMLの対応する `<camera label="...">` を確認します。例えばXMLが `IMG_0001.JPG` なら、COLMAP側のファイル名も `IMG_0001.JPG` である必要があります。名前が違う場合は、テンプレートを調整してCOLMAPを再出力します。元写真がJPEG以外、ラベルが独自名、複数フォルダに同名写真がある場合などは、この一致条件を特に確認してください。現行版には名前の自動変換・対応表の入力機能はありません。

生成された `cameras.txt` と `images.txt` の入ったフォルダをScale Bridgeのモデル入力に指定します。場所は出力構成によって異なるため、必ずしも `sparse/0` 固定ではありません。`points3D.txt` はなくても読み込めます。バイナリ形式を使う場合は `points3D.bin` も含む完全なモデルが必要です。

**Scale Bridgeで目盛りをクリックする画像には、今回COLMAPと一緒に書き出した歪み補正画像を指定します。後でMetashapeでメッシュを生成する予定でも、この打点用画像は歪み補正画像です。** 画像フォルダは全画像のままでも、スケールの打点に使う画像だけをコピーしたものでも構いません。コピー時は `images.txt` に記録されたファイル名・相対パスを保持します。書き出した画像には追加のリサイズ・切り抜き・回転を行いません。

### 3. AgisoftカメラXMLを書き出す

同じチャンクで、再びFile → Export → Export Camerasを開き、**Agisoft XML形式**で、例えば `original_cameras.xml` に保存します。カメラキャリブレーション画面から保存するセンサー単体のXMLではなく、カメラ配置を含むExport CamerasのXMLが必要です。

全アライン済みカメラを含め、COLMAPとカメラ集合を一致させます。XMLには元写真用の調整済みキャリブレーションとカメラ配置を保持します。COLMAP用のピンホール画像に合わせて元のセンサーキャリブレーションを変更する操作は不要です。現行版のXML変換は単一チャンク・参照座標なし・単眼カメラが対象で、リグ・複数component・マーカー／ground controlを含むXMLなどは対象外です。

このXMLをScale Bridgeの元XML入力に指定します。Scale Bridgeで歪み補正画像に打点して縮尺を計算した後、このXMLを基に `scaled_cameras.xml` を出力します。オリジナル入力画像での打ち直しは不要です。Metashapeへ戻さずCOLMAPだけを縮尺補正する場合、XMLは不要です。後段のMetashapeで使用する画像は「縮尺補正後にMetashapeでメッシュを生成する」を参照してください。

設定の参考：[Agisoft ExportCamerasパラメータ仕様](https://download.agisoft.com/metashape-java-api/latest/com/agisoft/metashape/tasks/ExportCameras.html)。この手順は現行コードの入力条件に合わせたもので、Metashape Standard実機での往復検証は未完了です。

## 入力と操作

### 用意する画像・カメラデータの範囲

**Scale Bridgeで表示する画像は、スケールの目盛りを打点する写真だけで構いません。COLMAPとAgisoft XMLは、同じチャンク・同じアラインメントの全アライン済みカメラ分をそのまま書き出してください。**

| 入力 | 用意する範囲 |
| --- | --- |
| 画像フォルダ | スケール設定・検証の打点に使う画像だけで可。各端点が最低2枚、推奨3枚以上で確認できること |
| COLMAPデータ | 全アライン済みカメラ分。打点用の写真だけにカメラ情報を削らず、書き出したモデルをそのまま使用 |
| 元のAgisoftカメラXML | XML出力を使う場合に必要。COLMAPと同じアラインメントの全アライン済みカメラ分 |
| OBJ／PLY | Scale Bridgeの縮尺計算には不要 |

例えば、300枚がアライン済みで、そのうち5枚にスケールが写っている場合、COLMAPとXMLは300台分のカメラ情報を保持し、Scale Bridge用の画像フォルダには打点に使う5枚だけを置く構成で使用できます。未アラインの写真はここでいう全アライン済みカメラには含みません。

画像名と相対パスはCOLMAPの画像名に一致させてください。COLMAPに記録された画像に対して、追加のリサイズ・切り抜き・回転を行わないでください。ピンホール変換ありでCOLMAPをエクスポートした場合、打点には同時に書き出した歪み補正画像を使い、元写真と混在させないでください。

GUIの「打点用写真」選択欄には、**指定した画像フォルダに実在するCOLMAP登録画像だけ**を表示します。スケールが写っている歪み補正画像だけを配置すれば、その画像だけを選択できます。フォルダ内にあってもCOLMAPに登録されていないファイルは表示しません。

一覧の上には「打点用画像／COLMAP登録／画像未配置」の件数を表示します。例えば300台分のカメラ情報と5枚の画像を指定すると、一覧は5枚、COLMAP登録は300台、画像未配置は295枚となります。**この絞り込みは写真選択欄だけに適用し、縮尺計算・COLMAP出力・XML対応付けに使う全カメラ情報は保持します。** スケールマーカーの有無を自動判定する機能ではないため、全画像を配置した場合は全画像が一覧に出ます。

対応画像が0枚の場合は一覧を無効化し、画像フォルダ・ファイル名・相対パスを確認する案内を表示します。画像フォルダやCOLMAPフォルダを変更したら「読み込み」を押して一覧を更新してください。寸法が異なる画像や破損画像は選択時にエラーを表示し、打点できません。以前の写真を残さず表示を消去します。保存済み作業を再開した場合、配置していない画像に対する保存済み打点も保持します。

1. Metashapeの同じチャンク・同じアラインメントから、**全アライン済みカメラ分**をExport CamerasでCOLMAP形式とAgisoft XML形式にそれぞれ書き出します。スケールが写っている写真だけに絞らず、両形式のカメラ集合を一致させます。
2. COLMAPの`cameras.txt`、`images.txt`が入ったフォルダ（通常`sparse/0`など）を選びます。完全なbinaryモデルも読み込めます。既存の`points3D.txt`は任意です。
3. **Scale Bridgeの打点用として、COLMAPと一緒に書き出した歪み補正画像のフォルダ**を選びます。このREADMEの推奨設定では、オリジナル入力画像をこの欄に指定しません。画像サイズ不一致は拒否しますが、同じサイズの別画像や歪み補正の違いを自動検出できるわけではありません。
4. XMLを書き出す場合は、元のAgisoftカメラXMLを選びます。「読み込み」を押します。
   写真はプルダウンに加え、**「前へ」「次へ」**ボタンで順に切り替えられます。現在の写真番号と総枚数を表示し、先頭では「前へ」、末尾では「次へ」を無効にします。写真を切り替えても登録済みの打点は保持されます。
5. 点名Aを選び、複数写真で同じ目盛りをクリックします。Bも同様に指定します。各点最低2枚、推奨3枚以上です。AとBが同じ写真集合に写っている必要はありません。
6. 距離表に`A / B / 100 / scale`のように入力します。入力距離はmmです。
7. 使用できる点名は**A〜Eの5点**です。距離表には、縮尺決定用の`scale`を最大3区間、独立検証用の`check`を最大2区間、合計5区間まで入力できます。「点」は写真上の物理的な目盛り位置、「区間」は2点間の既知距離です。点は複数区間で共有できます。例えばscaleをA–B・A–C・A–D、checkをB–E・C–Eと指定できます。`check`は倍率計算に使いません。距離を追加すると、scaleが3区間になるまでは`scale`、それ以降は`check`が初期入力されます。必要な用途・端点・実寸へ修正してください。
8. 「縮尺を計算」で倍率、写真別再投影誤差、交会角、距離の残差を確認します。打点は同じ点・同じ写真をクリックすると更新されます。画像上のカーソルは**丸の中に十字のターゲット**です。**十字の中心が実際の打点位置**です。白い縁取りで明暗の異なる写真でも見やすくしています。左クリックで打点し、ホイールで拡大、左ドラッグで移動できます。ドラッグ移動では打点を追加しません。
9. COLMAP出力単位をmまたはmmから選び、新しい出力フォルダへ保存します。XML出力は常にmです。元ファイルは上書きしません。
10. 「作業を保存」でJSONに記録できます。GUIで保存する画像・モデルのパスは保存時の絶対パスです。相対パスの場合はsessionファイルのあるフォルダを基準に解決します。別PCへ移す場合はJSONの`paths`を変更してください。カメラデータの変更はfingerprintで検出し、以前の打点の復元を拒否します。

ファイル名の空白・タブはCOLMAP公式textリーダーで安全に扱えないため、この版では拒否します。元の画像名を修正して再書き出ししてください。画像はEXIFによる自動回転をしません。COLMAP画像名に対する表示方向と寸法が一致することを確認してください。

### 再投影誤差を確認して打点を修正する

「縮尺を計算」後、打点一覧の末尾の**「再投影誤差 px」**列に、マーカー・写真ごとの誤差を小数点以下3桁で表示します。単位は表示倍率に依存しない元画像のピクセルです。判定には丸める前の値を使います。

- 「最大再投影誤差」（初期値**10.0 px**）を超える行は赤字で「超過」と表示します。警告にも点名（A〜E）と該当写真名が表示されます。保存済みの作業を再開すると、その作業に記録されている判定値を復元します。旧作業の2 pxを10 pxに変更したい場合は、GUIで変更して再保存してください。
- 閾値を超える点があっても他の点まで診断し、計算できた各行の誤差を残します。交会角不足・観測不足などで三角測量できない点は「計算不可」と表示し、理由を結果欄と誤差セルのツールチップで確認できます。
- 閾値超過などで計算が止まった場合、縮尺は確定せず、COLMAP・XMLを書き出せません。該当写真で同じ物理的位置を打っているか確認し、拡大して修正してください。登録した点は距離に未使用でも診断対象です。不要な打点は削除してください。
- 打点・距離・判定値などの入力を変更すると、以前の誤差と縮尺を無効にし、誤差列を「—」に戻します。修正後は再び「縮尺を計算」を押してください。

### 規定マーカースケールの自動検出と一括計算

自動検出の第一版は、**AprilTagのtag16h5・tag25h9・tag36h10・tag36h11**に対応しています。**Metashapeの12bit円形コード、Circle21h7、Standard41h12・52h13は、この版では自動検出しません。** 対応外のマーカーは手動打点を使用してください。検出にはOpenCVを使用し、学習モデルやGPUは必要ありません。

更新後は仮想環境を有効にして、追加の依存関係をインストールしてください。

```bash
python -m pip install -r requirements.txt
```

1. 通常と同様に、COLMAPと対応する歪み補正画像を読み込みます。
2. 「規定マーカースケール」→「設定」を開き、印刷に使用したAprilTagファミリーと、A〜EへのタグIDの割り当てを登録します。タグIDはコードに符号化された整数です。印刷PDFの表示名や通し番号と同じとは限らないので対応を確認してください。使わない点のIDは空欄にします。同じファミリー・同じIDのタグを複数の場所で使用しないでください。
3. 実測した**マーカー中心間距離（mm）**と用途を入力します。scaleは1〜3区間、checkは0〜2区間です。空欄の区間は使用しません。IDや印刷サイズから実測距離を推測する機能はありません。
4. 「設定を保存」で規定スケールをJSONに保存できます。次回以降は「設定を読み込む」で同じID・距離を再利用します。規定スケールは作業保存JSONにも含めます。
5. **「自動検出 → 距離適用 → 計算」**を押すと、写真一覧にある全画像を検出し、登録IDの中心位置を打点として登録、規定距離を距離表へ適用した後、縮尺・再投影誤差・検証距離の残差を自動計算します。検出処理は別スレッドで実行し、進捗と画像名を表示します。
6. この一括処理は、**現在の打点と距離表を規定スケールの検出結果で置き換えます**。既存の手動作業を残す場合は、先に「作業を保存」してください。検出中の画像破損・寸法不一致・指定IDの重複などで検出自体が中断した場合は、既存の打点・距離表を保持します。
7. 各点の検出枚数が2枚未満、交会角不足、閾値超過などの場合は縮尺を確定せず、点名と理由、算出できた再投影誤差を表示します。検出された打点は残るため、画像上で位置を確認・手動修正し「縮尺を計算」で再計算できます。自動検出で見つからなかった位置を推定して補うことはありません。
8. 正常終了後、通常のCOLMAP・XML書き出しを使用します。書き出し自体は自動で行いません。自動検出直後の計算記録には規定スケール・画像別検出ID・点別検出枚数も含まれます。

タグの中心は、検出した四隅の単純平均ではなく、射影変換でタグ平面の中心を画像へ写した位置を使います。自動検出も実画像で精度確認が必要です。マーカーを小さく写しすぎた写真、ぼけ、反射、遮蔽、印刷の変形は検出率と測定精度に影響します。

## 縮尺補正後にMetashapeでメッシュを生成する

ここからは、**Scale Bridgeで歪み補正画像に打点し、縮尺を計算して `scaled_cameras.xml` を出力した後**の工程です。打点用画像を選ぶ手順ではありません。

1. Metashapeで別プロジェクトまたは新規チャンクを作り、**最初のアラインメントに使用したオリジナル入力画像のうち、全アライン済みカメラに対応する画像**を追加します。ここではCOLMAP書き出し時の歪み補正画像を追加しません。スケールが写っている画像だけでなく、メッシュ生成に使用する全画像を追加します。`scaled_cameras.xml` は、このオリジナル入力画像用のキャリブレーションを保持しています。
2. File → Import Camerasで`scaled_cameras.xml`を読み込みます。カメララベルと写真名は大文字・小文字も一致させます。
3. 必要に応じてTools → Tie Points → Build Point Cloudでタイポイントを構築し、領域を確認して深度マップ・メッシュを生成します。
4. 通常のAlign Photosを再実行すると、与えたカメラ配置を再推定して縮尺が変わる可能性があります。まず読み込んだ配置を使って生成してください。検証前にOptimize Camerasも実行しません。
5. OBJ/PLYを書き出し、外部の計測ソフトでスケール設定用距離および別の既知距離を測定します。100 mmを入力した場合、m出力で0.100となることを確認します。

**XMLの再読み込みで既存メッシュや既存の深度マップが一括補正されるとは扱いません。** 新規チャンクでの再生成を対象とします。Standardのバージョン別に読み込み挙動を検証する必要があります。

XMLの対象は、単一チャンク・参照座標なし・単眼カメラのカメラ書き出しです。対応づけに最低3台の非共線カメラ配置が必要です。リグ、複数component、地理/投影座標、マーカー/ground control付きXML、行列形式のchunk transform等は誤変換を避けるため拒否します。COLMAP側のリグは公式APIを使って縮尺補正します。

## デモ

同梱の`example_demo/complete_session.json`を「作業を再開」で読み込むと、合成画像と正解の打点を表示できます。`blank_session.json`は打点練習用です。

実際の写真ではない、100 mmスケールを含む合成画像を生成できます。

```bash
python make_demo.py demo
python gui.py
```

`demo/blank_session.json`で打点を練習できます。`demo/complete_session.json`には正解の打点が入っています。GUIの「作業を再開」で読み込み、「縮尺を計算」を押してください。倍率の正解は0.1 m/モデル単位、検証距離A–Cは80 mmです。デモは数学的動作を確認するもので、実写真の精度保証ではありません。

## CLI

GUIで保存したsessionを再計算し、カメラを出力します。

```bash
python cli.py demo/complete_session.json --colmap-output demo/scaled_colmap --xml-output demo/scaled_cameras.xml --report demo/result.json
```

## テスト

```bash
python -m pip install pytest
QT_QPA_PLATFORM=offscreen python -m pytest -q
```

テストには、5種類のレンズモデル、カメラ回転、2視点/複数視点三角測量、打点ノイズと外れ値、退化配置、複数距離と検証区間、m/mm、text/binary、リグ、XMLの倍率換算・回転保持・誤った対応の拒否、Qtのマウスイベントと結果の無効化が含まれます。

## ファイル

- `core.py`: 計算・モデル入出力
- `gui.py`: PySide6打点GUI
- `cli.py`: 保存sessionのバッチ処理
- `make_demo.py`: 合成画像とXML・sessionの生成
- `ALGORITHM.md`: 座標規約、数式、入力/出力書式、検証範囲
- `tests/`: 数値およびGUIテスト

## 限界

一様縮尺のみを補正します。非線形歪み、局所的なモデル変形、動いたスケール、誤った目盛り対応を修正する機能ではありません。再投影誤差は写真上の整合性であり、実寸誤差の上限ではありません。交会角1°、再投影誤差10pxは初期判定値で、測定精度の保証値ではありません。GUIで変更できます。検証距離の誤差が1%を超えた場合は注意表示します。自動検出は別スレッドで行いますが、モデルの読み込み/出力と縮尺計算は同期処理のため、大規模点群の付いたモデルではGUIが一時停止することがあります。
